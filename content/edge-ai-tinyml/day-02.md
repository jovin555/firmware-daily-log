## The Core Concept

A neural network is just a stack of linear algebra operations followed by nonlinear "squashing" functions. For embedded engineers, the key insight is that **every operation costs memory and cycles**. A fully connected layer with 256 inputs and 128 outputs requires 32,768 multiplications and 32,768 additions per inference. On a 100 MHz MCU, that's measurable time.

The neuron itself is simple: `y = f(W * x + b)`. The weight matrix `W` and bias vector `b` are what we store in flash. The input `x` comes from a sensor or feature extractor. The activation function `f` (ReLU, sigmoid, tanh) introduces nonlinearity—without it, stacking layers would be equivalent to a single linear transform.

Why this matters for embedded: you don't train on-device (usually). You train on a server, then **export the weights and architecture** to run inference. Your job is to implement that forward pass efficiently, often in fixed-point arithmetic because floating-point units are rare on low-power MCUs.

## Key Commands / Configuration / Code

Let's walk through a minimal C implementation of a single dense layer with ReLU activation. This is the core of every TinyML model.

```c
// dense_layer.h
#ifndef DENSE_LAYER_H
#define DENSE_LAYER_H

#include <stdint.h>

// Fixed-point representation: Q7 (1 sign bit, 7 fractional bits)
// Value range: [-1.0, 0.9921875]
typedef int8_t q7_t;

// Layer configuration struct
typedef struct {
    uint16_t input_size;   // number of input neurons
    uint16_t output_size;  // number of output neurons
    const q7_t *weights;   // pointer to weight array (input_size * output_size)
    const q7_t *bias;      // pointer to bias array (output_size)
    q7_t *output;          // pointer to output buffer (output_size)
} DenseLayer;

// Forward pass: y = relu(W * x + b)
// All values are Q7 fixed-point
void dense_forward_q7(DenseLayer *layer, const q7_t *input) {
    for (uint16_t o = 0; o < layer->output_size; o++) {
        int32_t sum = 0;
        
        // Dot product: accumulate with 32-bit intermediate to avoid overflow
        for (uint16_t i = 0; i < layer->input_size; i++) {
            sum += (int32_t)layer->weights[o * layer->input_size + i] * (int32_t)input[i];
        }
        
        // Add bias, then shift back to Q7 (product of two Q7 is Q14, we want Q7)
        sum += ((int32_t)layer->bias[o]) << 7;  // bias is Q7, shift to align
        sum = sum >> 7;  // scale back to Q7
        
        // ReLU: clamp negative to zero
        if (sum < 0) sum = 0;
        if (sum > 127) sum = 127;  // saturate to max Q7
        
        layer->output[o] = (q7_t)sum;
    }
}
#endif
```

To use this, you'd load weights from a header file generated by your training framework (e.g., TensorFlow Lite for Microcontrollers exports C arrays). Here's a minimal test harness:

```c
// main.c
#include "dense_layer.h"

// Example: 4 inputs -> 3 outputs
#define INPUT_SIZE  4
#define OUTPUT_SIZE 3

// Pretend weights and biases (would come from training)
const q7_t weights[INPUT_SIZE * OUTPUT_SIZE] = {
    10, -5,  3,  2,   // neuron 0
    -8,  7, -1,  4,   // neuron 1
     6,  0, -9,  1    // neuron 2
};

const q7_t bias[OUTPUT_SIZE] = {5, -3, 2};

int main(void) {
    q7_t input[INPUT_SIZE] = {10, 20, -15, 5};
    q7_t output[OUTPUT_SIZE];
    
    DenseLayer layer = {
        .input_size  = INPUT_SIZE,
        .output_size = OUTPUT_SIZE,
        .weights     = weights,
        .bias        = bias,
        .output      = output
    };
    
    dense_forward_q7(&layer, input);
    
    // output[0] = relu((10*10 + 20*(-5) + (-15)*3 + 5*2 + 5) >> 7)
    // = relu((100 -100 -45 +10 +5) >> 7) = relu(-30 >> 7) = 0
    // output[1] = relu(...) = 2
    // output[2] = relu(...) = 0
    
    return 0;
}
```

For real deployment, you'd use CMSIS-NN or a vendor-optimized library. The above is for understanding, not production.

## Common Pitfalls & Gotchas

**1. Forgetting about intermediate overflow.** When you multiply two 8-bit fixed-point numbers, the product needs 16 bits. Accumulate in a 32-bit integer. I've seen countless bugs where `int8_t * int8_t` overflows silently in C—the result is undefined behavior, and your inference goes haywire.

**2. Misaligning the fixed-point scale.** If your weights are Q7 (1.7 format) and your input is also Q7, the product is Q14. You must shift right by 7 to get back to Q7. If you shift by 8, you lose precision. If you don't shift, your output range explodes. Always verify with a known test vector.

**3. ReLU is not free on all MCUs.** On Cortex-M4 with DSP extension, `max(0, x)` is one instruction. On a basic Cortex-M0, it's a branch. For tiny models, the activation function overhead can be 10-20% of total inference time. Consider using ReLU6 (clamp to 6) if you need quantization-friendly behavior—it's common in TFLite Micro.

## Try It Yourself

1. **Modify the dense layer to use ReLU6 instead of ReLU.** Change the saturation check to clamp between 0 and 6 (in Q7, that's 0 and 48). Run the same test vector and observe the output difference.

2. **Profile the forward pass.** On your dev board (e.g., STM32F4 Discovery), toggle a GPIO pin before and after `dense_forward_q7()`. Use an oscilloscope or logic analyzer to measure execution time. How many cycles per multiply-accumulate?

3. **Stack two layers.** Create a second `DenseLayer` struct that takes the first layer's output as input. Chain them to form a 2-layer MLP. Verify that the output matches a Python reference (use NumPy with the same weights and biases).
