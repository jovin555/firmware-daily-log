## What I Explored Today

Today I went from a `.tflite` model file to a running inference on an ARM Cortex-M4 dev board. The goal was to understand the full build-and-flash pipeline for TFLite Micro: cross-compiling the runtime, linking my model as a C array, and getting the binary onto hardware via OpenOCD. I used the Arduino Nano 33 BLE Sense (nRF52840) as my target, but the workflow applies to any Cortex-M board with a TFLite Micro port.

## The Core Concept

TFLite Micro is not a library you `apt-get install`. It's a set of C++ source files you compile directly into your firmware. The "why" is important: embedded targets lack dynamic linking, virtual memory, and often a filesystem. By compiling the interpreter into the same binary as your application, you get deterministic memory usage and no runtime dependency on an OS.

The pipeline has three stages:
1. **Model conversion** — Convert a Keras/PyTorch model to a quantized `.tflite` flatbuffer, then to a C byte array (`xxd`).
2. **Build integration** — Include the model array in your firmware, initialize the TFLite Micro interpreter with a pre-allocated tensor arena.
3. **Flash & debug** — Cross-compile with the correct toolchain, flash via SWD/JTAG, and verify inference via serial output.

The critical insight: TFLite Micro's `MicroInterpreter` does not allocate memory at runtime. You provide a static `tensor_arena` buffer (typically 2–10 KB for small models). If your arena is too small, the interpreter silently fails or returns an error code. This is the number one cause of "it compiled but doesn't run" issues.

## Key Commands / Configuration / Code

### 1. Convert model to C array (after training)
```bash
# Assuming you have a quantized model.tflite from post-training quantization
xxd -i model.tflite > model_data.cpp
# This generates:
# unsigned char model_tflite[] = { ... };
# unsigned int model_tflite_len = 12345;
```

### 2. Minimal inference main.cpp
```cpp
#include "tensorflow/lite/micro/all_ops_resolver.h"
#include "tensorflow/lite/micro/micro_interpreter.h"
#include "model_data.h"  // generated by xxd

// Tensor arena — adjust size based on model requirements
constexpr int kTensorArenaSize = 10 * 1024;  // 10 KB
alignas(16) uint8_t tensor_arena[kTensorArenaSize];

void setup() {
    Serial.begin(115200);
    while (!Serial);  // wait for serial monitor (Arduino-specific)

    // 1. Load all built-in ops (or use MicroMutableOpResolver for smaller footprint)
    static tflite::AllOpsResolver resolver;

    // 2. Create interpreter
    static tflite::MicroInterpreter interpreter(
        tflite::GetModel(model_tflite),  // from model_data.h
        resolver,
        tensor_arena,
        kTensorArenaSize
    );

    // 3. Allocate tensors — this is where arena size is validated
    TfLiteStatus allocate_status = interpreter.AllocateTensors();
    if (allocate_status != kTfLiteOk) {
        Serial.println("AllocateTensors() failed — increase tensor arena!");
        while (1);  // halt
    }

    // 4. Get input tensor and set data (example: single float input)
    float* input = interpreter.input(0)->data.f;
    input[0] = 1.5f;  // your preprocessed input

    // 5. Run inference
    TfLiteStatus invoke_status = interpreter.Invoke();
    if (invoke_status != kTfLiteOk) {
        Serial.println("Invoke failed");
        while (1);
    }

    // 6. Read output
    float* output = interpreter.output(0)->data.f;
    Serial.print("Output: ");
    Serial.println(output[0]);
}

void loop() {
    // Run once, then sleep
}
```

### 3. Cross-compilation with CMake (Arduino CLI example)
```bash
# Install Arduino CLI and required core
arduino-cli core install arduino:mbed_nano

# Compile with TFLite Micro source
# You need to point to the TFLite Micro repo root
ARDUINO_LIBRARIES=./tensorflow/lite/micro/tools/make/gen/arduino_x86_64/arduino_build/
arduino-cli compile --fqbn arduino:mbed_nano:nano33ble \
    --libraries $ARDUINO_LIBRARIES \
    ./my_inference_app/
```

### 4. Flash via OpenOCD (if not using Arduino bootloader)
```bash
openocd -f interface/cmsis-dap.cfg -f target/nrf52.cfg \
    -c "program my_inference_app.elf verify reset exit"
```

## Common Pitfalls & Gotchas

### 1. Tensor arena too small
The `AllocateTensors()` call returns `kTfLiteError` if the arena can't fit all intermediate tensors. **Always check the return value.** Start with 10 KB for a simple model (e.g., keyword spotting with 10–20 ops). For larger models, you may need 50–100 KB. Use the `interpreter.arena_used_bytes()` method after allocation to see the exact requirement.

### 2. Missing ops in the resolver
`AllOpsResolver` includes every TFLite Micro op (~100+), which bloats flash. For production, use `MicroMutableOpResolver` and register only the ops your model uses. If you forget one, `AllocateTensors()` will fail with a cryptic error. To find required ops:
```bash
# From the .tflite file
flatc -t --raw-binary model.tflite | grep "builtin_code"
```

### 3. Alignment and memory corruption
Tensors must be aligned to 16 bytes on ARM Cortex-M4 (due to SIMD instructions). Declare your arena with `alignas(16)` as shown above. Without it, you may get hard faults or silent data corruption during inference.

## Try It Yourself

1. **Measure arena usage** — Add `Serial.print(interpreter.arena_used_bytes());` after `AllocateTensors()` and compare to your `kTensorArenaSize`. Reduce the arena to exactly the used size + 256 bytes margin.

2. **Switch to mutable resolver** — Replace `AllOpsResolver` with `MicroMutableOpResolver<10>` and register only the ops from your model. Measure the flash size difference (`arduino-cli compile --verbose` shows the .elf size).

3. **Add a second inference** — Modify the `loop()` function to run inference every second with a different input. Print both outputs and verify the interpreter state is properly reset between invocations (it should be — TFLite Micro is stateless between `Invoke()` calls).
